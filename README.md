# 日本株 反転初動スクリーニングシステム

約3,500銘柄の日足から、すでに上がった株ではなく **下落後、BB下限・低位RSI・足型・ストキャスで反転を確認した初動** を抽出し、材料と実績を検証するプロジェクトです。これは売買助言ではありません。

## AI社員2人の投資会議と300万円運用

### Phase 1 夜会（銀行セクター）

`python -m src.investment_meeting --kind night --no-notify` は銀行だけを対象に、2年・10年・30年の
日本国債金利、前日・5日変化、10年-2年スプレッドと個別テクニカルを統合した夜会レポートを
`reports/meeting/night/` へ Markdown と JSON で保存します。夜会分類は「押し目候補／動意候補／翌朝再確認／避ける」
だけで、結果は常に `status=provisional`、`final_decision=false`、翌営業日の朝会開始時刻まで有効です。
朝会はこのファイルを参考情報と再確認条件として表示するだけで、主力・小口への自動昇格、注文方式、株数、
逆指値、損切り、利確、RR、資金管理には入力しません。

半導体、建設、資源、電力、防衛、不動産、商社は同じ「セクター環境→個別タイミング→暫定4分類」契約へ
将来追加する設計に留めます。自社株買い・IR・監理整理・上場廃止等も、監査可能な公式取得元、取得時刻、
識別子、欠損時の評価不能を共通入力契約にする設計のみで、本格自動取得は Phase 1 に含みません。

`src.investment_meeting` と `src.order_planner` は自由作文やLLM呼び出しではなく、保存済み入力 → 設定済み閾値 → 分析担当判定 → 注文方式比較 → 資金配分の順で、同じ入力から常に同じ最終注文案を返します。朝会の成果物は候補一覧ではなく、主力／小口／監視／見送り、成り行き／指値／逆指値／見送り、買いゾーン、逆指値、追いかけ禁止、損切り、利確、株数、必要資金、最大損失、RRです。証券会社への自動注文は一切行いません。投資分析担当は押し、RSI・BB・ストキャス・足型、出来高、急騰と暴落リバウンドを確認し、運用・検証担当はRR、損失上限、現金、売買単位、投入額と保有上限を確認します。意見が割れた場合は **主力候補 → 小口候補 → 監視 → 見送り** のうち慎重な方を採用します。急騰済みと5%以上のギャップは見送り、出来高0.6倍未満は主力から除外、3日-10%・5日-15%・25日線乖離-10%以下の暴落リバウンドは小口以下です。候補ゼロは異常ではなく「本日は新規買いなし」と報告します。

資金ルールは `config.json` の `portfolio` に集約しています。既定は資産300万円、1取引リスク0.7%（21,000円）、1銘柄50万円、最大5銘柄、最低現金25%、100株単位です。主力100%、小口50%、暴落リバウンド25%も変更できます。株数はリスク上限と投入可能額の小さい方を100株単位へ切り下げるため、条件を満たせない銘柄は買いません。`current_cash` と `current_positions` は実残高に更新してください。

### 市場環境・重大ニュースを先に判定

日本国債は2年・10年・30年利回りと、前日・5日・20営業日のbp変化、10年-2年スプレッドを `data/jgb_yields.csv` に保存します。取得できない年限や比較期間は補間・推測せず欠損とし、Discord朝会とStreamlitにも同じ状態を表示します。観測できた10年金利の20日変化だけを設定済み感応度で銀行・保険・グロース・不動産・電力ガスの業種影響へ反映します。AI研究員は金利局面・イールドカーブ局面別の実績を検証しますが、本番ルールは自動変更しません。

朝会は個別株より先に `src.market_environment` で市場を判定します。対象は日経225先物、TOPIX、S&P 500、NASDAQ、SOX、VIX、ドル円、米10年債利回り、WTI、金です。`yfinance` で取得できた終値だけを使い、現在値、前日終値、前日差・率、短期変化を保存します（米10年債はbp差も保存）。欠損値は補間・推測せず除外します。検証や確定データ優先時は `data/market_input.csv` に入力できます。

各変化を `config.json` の `market_environment.indicator_rules` で -2～+2 に離散化し、ウェイトを掛けた合計を「強いリスクオン／リスクオン／中立／警戒／強いリスクオフ」にします。既定境界は +6、+2、-2、-6、資金係数は順に100%、100%、75%、50%、25%です。警戒では主力を小口へ降格し、強いリスクオフでは強い業種追い風がない新規主力を停止します。市場係数は従来の300万円、1取引損失、投入額、現金、保有数制約を適用した株数へ掛けます。緊急ニュース時は新規買いを停止します。

`sector_impacts` は市場値を全銘柄へ一律加点しません。SOXは半導体・電子部品・製造装置、米金利はグロースと銀行・保険、ドル円は自動車・輸出と輸入コスト業種、WTIは石油・資源と航空・運輸へ異なる符号・倍率で反映します。マッピングと倍率は設定変更可能です。

ニュースは `data/news_input.csv` へ入力します。必須監査情報は取得元、取得時刻、タイトル、URLまたは識別子です。`trusted_sources` にない取得元、またはURL/識別子がない行は保存しても売買スコアを0にします。タイトルとURLで重複除去し、LLMなしで災害、戦争、金融危機、関税、半導体規制、原油、金融政策、企業好悪材料、M&A等を分類します。重大度1～5、方向-2～+2、範囲、業種、銘柄、継続性と `重大度×方向` を保存します。大規模災害・金融不安等は `emergency_risk` になります。企業好材料も急騰除外を覆さず、材料後に上がり切った株を追いません。

監査CSVは `data/market_environment.csv`、`data/news_events.csv`、`data/sector_impact.csv` です。最終候補にはファンダメンタル、テクニカル、反転確認、市場、業種、ニュース、資金・リスクの内訳を保存します。朝会Discordは冒頭に主要指標、市場判定、重大ニュース、資金方針を表示します。8:30は取得可能な変化だけを再確認し、取得できない値を作りません。

### JPX公式の信用取引週末残高

候補銘柄の信用取引データは、JPX公式「銘柄別信用取引週末残高」を第一取得元かつ唯一の取得元として、
最新週と前週を銘柄コードで照合します。候補CSVと `data/jpx_margin_balances.csv` に売残、買残、各前週比、
信用倍率（買残÷売残）、基準日、取得元URL、取得日時を保存します。売残0は無限大にせず
`算出不能・売残0` とします。ページ・Excel形式の変更、通信失敗、最新週または前週を取得できない場合、
および銘柄欠損では推測も前回値補完もせず `データなし` とし、スキャンと会議は続行します。

### 市場データの許可済みフォールバック

`config.json` の `data_sources.instruments` が取得許可リストです。各 source の
`enabled`、`priority`、`allowed_for_automation`、`timeout`、`instrument_type` を確認してから、
優先度の小さい順に取得します。標準の順序は日本国債 2Y/10Y/30Y が財務省→Yahoo Finance、
米10年金利が FRED→Yahoo Finance、VIX が Cboe→Yahoo Finance です。TOPIX は Yahoo Finance
のみを試し、取得できなければ欠損として扱います（継続利用できる公式 JPX 自動取得 URL を未確認のため）。
WTI は EIA の Cushing 現物価格を `WTI_SPOT` として取得し、先物 `CL=F` とは相互補完しません。
その他の既存指標は、それぞれ同一定義の Yahoo Finance 系列だけを使用します。

各試行は成功・失敗を問わず `data/source_audit.csv` に追記されます。HTTP 403、HTTP 429、
timeout、empty data、parse error、schema change、通信エラー、Secret 不足を別々に記録します。
全取得元が失敗した instrument は欠損のまま朝会を続行し、推測・前回値補完はしません。
`compare_sources` を `true` にした場合は許可済みの同一定義系列をすべて取得し、第1優先値との差を
監査CSVの `comparison_source` / `difference` に保存します（通常は不要な外部アクセスを避けるため
`false`）。EIA の利用には環境変数 `EIA_API_KEY` が必要です（未設定時は当該ソースを欠損扱いにし、朝会は継続します）。
`data_sources.max_age_business_days` を超えた観測値は `stale_data` として監査し、次順位のソースへフォールバックします。財務省、FRED、Cboe、Yahoo
Finance の現在の設定には Secret はありませんが、運用開始前に各提供元の最新利用条件、再配布条件、
アクセス頻度を組織として再確認してください。

ニュースは官公庁、中央銀行、TDnet/EDINET、JPX、企業自身の IR の公式 RSS/API または監査可能な
入力だけを信頼対象にします。みんかぶ、株探、世界の株価マーケット等の HTML スクレイピングは
実装していません。

APIキーや追加Secretは必須ではありません。市場データは無料データ源の遅延・欠損・ティッカー仕様に依存します。ニュースRSS/APIの自動収集器は未同梱なので、現状は信頼できる公的発表・IR・取引所開示等をCSVへ投入してください。ニュース本文の意味理解、企業の輸出比率・原油感応度、高PER判定は構造化入力がない限り推測しない既知の制限です。

```bash
python -m src.investment_meeting --kind morning --no-notify
python -m src.investment_meeting --kind recheck --no-notify
python -m src.investment_meeting --kind close --no-notify
```

05:45 JST（20:45 UTC）に全銘柄スキャンを開始し、06:30 JSTまでのDiscord最終注文案を目標にします。レポートは `reports/meeting/{morning,close,weekly}/` へ保存します。8:30再確認は前日終値しかない場合に「6:30朝会から更新なし」と明示し、疑似価格を作りません。大引け後は候補結果・警戒・翌日監視、週次は勝率、PF、MFE/MAE、最大DDおよび見送り後の値動きを `data/performance.csv` と候補履歴で検証する入口です。AI社員は提案を `reports/proposals/` に書けますが、設定や売買ロジックを自動変更しません。

### 決定論的な注文価格と方式

逆張りは「安いから買う」のではなく、`反転確認高値=max(前日高値, 反転足高値, 直近2日高値)`、`逆指値=反転確認高値+ATR14×0.1`（設定可）を基本にします。追いかけ禁止は `max(逆指値+ATR×0.5, 逆指値×1.03)` です。指値の買いゾーンは前日終値、BB -1σ/-2σ、MA25、20日支持線をアンカーにATR幅を加減して算出します。損切りは直近安値、反転足安値、BB下限、ATRストップの慎重側、利確は実エントリーから既定RR 2.0（研究値1.5/2.0/2.5）です。

成り行きは反転確認済み、出来高1.2倍以上、ギャップ3%以下、RSI過熱なし、急騰なし、かつ蓄積済み寄り成りPF 1.1以上の場合だけです。その他の逆張り反転足は逆指値、支持帯への押しを待てる形は指値です。寄値・気配が取得できない8:30再確認では推測せず「朝会から判断変更なし」とします。

株数は `資産×0.7%÷(実エントリー−損切り)` と投入額上限の小さい方を100株単位で切り下げます。主力100%、小口50%、暴落リバウンド25%、1銘柄50万円、最大5保有、同一業種2銘柄、現金25%以上を全候補へ順番に適用します。主力は総合順位点順の最大3銘柄で、4位以下は監視です。

### 注文方式別の仮想売買

`src.backtest` は同じシグナルを寄り成り・指値・逆指値で並行評価し、約定件数／率／平均価格、1/3/5/10日損益、MFE、MAE、勝率、平均利益／損失、PF、最大DDを `data/order_method_performance.csv` に保存します。到達しない注文は未約定（損益欠損）として、未約定後の最大上昇・下落だけを別記録します。週次AI研究員は方式PF、エントリー、逆指値幅、追いかけ禁止幅、RR候補の改善案を `reports/proposals/` に保存しますが、本番設定を変更しません。

## 独立戦略と優先順位

日足スキャナーは「BB逆張り」「BB＋RSI＋ストキャス」「底固め」「自社株買い」「決算・上方修正」を別々に記録します。材料だけでは候補にせず、価格による反転確認を必須とします。

BB逆張りは前日が20日BB -1σ以下（-2σ以下をより高得点）で、終値上昇または陽の包み・長い下ヒゲ・前日安値割れ回復・下落後陽線を必要とします。RSI14は25～40から前日比上昇、直近数日30以下からの上昇を重視します。7%K/10%Dは25以下から上向き、高値圏は評価しません。S=15点以上、A=11～14、B=8～10（すべて設定可）です。

底固め候補は10日を基本に、安値切り上げ、ATR低下、BB幅収縮、出来高減少後の増加、RSI安値切り上げ、レンジ上限突破を計測し、3条件以上かつ安値切り上げまたは突破を要求します。「玉集め」と断定する機能ではありません。

## 日足条件とスコア

基本条件は「%D の3日前比の方向」「%K の直前の押し／戻り」「最新足での %K 反転」です。買い側はさらに、直近2～5日の下落、RSI40以下・ストキャス売られ過ぎ・BB下限からの反転、陽の包み足、下ヒゲ、出来高増を中心に加点します。既定配点は `config.json` の `weights` が唯一の設定元です。

すでに急騰した買いシグナルは、当日/3日/5日騰落率、25日線乖離、RSI14、BB位置、ATR比の当日値幅で判定します。既定では当日+8%、3日+12%、5日+18%、25日線乖離+10%、RSI 72、BB +2.2σ、またはストップ高に近い値動きのいずれかで通常S/Aから強制除外します。全閾値は `config.json` の `surge_exclusion` で変更できます。除外行も分析用CSVに `除外理由=急騰済み（…）` として残しますが、Discordと15分足watchlistには入りません。

急騰除外は当日+8%、3日+12%、5日+18%、25日線乖離+10%、RSI72、BB +2.2σ以上、またはATRを伴う+7.5%以上のいずれかです。該当行は原則S/Aにせず「除外」として別CSVにも残します。+1～+4%程度の初反転はこの既定値では除外しません。

## 材料CSVと自社株買い

信頼できない材料を推測・自動生成しません。`data/buybacks.csv` と `data/events.csv` に、適時開示等で確認した値と情報源URLを手動入力します。自社株買いCSVは発表日、コード、上限株数・金額、期間、発行済株式数、時価総額、発表時株価、平均売買代金を保存し、時価総額比、発行済株式比、期間日数、1日想定取得額、売買代金比を計算します。既定は時価総額比または発行済株式比5%以上を高評価しますが、急騰済みなら除外します。

検出する足型は、色反転、包み足、はらみ足、長いヒゲ、前日高安値を抜けて戻る形、買い側の続落後陽線です。足型だけで候補にはしません。

## 自動検証

`src.backtest` は各候補の1/2/3/5/10/20日後終値と騰落率、20日間の最高/最安、最大上昇/下落率を記録します。`summary()` は件数、勝率、平均利益/損失、PF、最大ドローダウン、平均最大上昇/下落を戦略別にも返します。無料価格データには配当・分割・欠損等の限界があり、材料の正確な自動取得、手数料、スリッページ、出来高制約は今後の課題です。

## Streamlit

上部に資産・現金・保有数・主力／小口数・損失上限を表示し、AI社員2人の根拠と最終注文案を一覧表示します。注文方式比較では寄り成り・指値・逆指値のサンプル数、約定率、勝率、平均損益、PF、MFE、MAE、最大DDを表示します。チャートには買いゾーン上下、逆指値、追いかけ禁止、損切り、利確ラインを表示します。候補選択でローソク、BB、MA25/75/200、出来高、RSI、%K/%D、BUY日を表示します。候補CSVのアップロードに対応し、今日の会議結果、`data/signal_history.csv` に保存された過去の会議履歴、画面で日付・ランク・コード／会社名を絞り込んだ現在の結果を、日付入りファイル名のUTF-8 BOM付きCSVとしてダウンロードできます。空CSVでも停止しません。底固め期間の数値列は保存されますが、チャートのレンジ帯シェーディングは今後の改善点です。

## 15分足と重複防止

日足スキャンの入口で株価300円未満、20日平均出来高10万株未満、20日平均売買代金3億円未満を除外します。さらに直近5日の出来高倍率が5倍以上、またはATR14が株価の8%以上なら仕手株リスクとして候補・通知対象から外します。

テクニカル通過後は公式ファンダメンタルを取得し、必須項目が十分でスコア6点以上、かつ下方修正・赤字転落・債務超過・不祥事・重大事故がない銘柄だけを買い監視リストと日足Discord通知へ進めます。データ不足は推測せず不通過とします。

日足S/Aだけをスコア順に最大50銘柄まで `data/watchlist.json` に保存します（`scan.watchlist_ranks` / `scan.watchlist_max_stocks` で変更可能）。15分足は全上場株ではなく、このリストだけを監視します。通知には **%K反転、パラボリックSAR転換、ローソク方向の一致をすべて必須** とします。%K/%Dクロスと20本比の出来高増は補足表示に使いますが、それだけでは通知しません。足の開始時刻から15分経過したかを判定して形成中の足だけを除外し、**最新確定足を遅らせずに評価**します。`data/alert_state.json` の「コード・確定足時刻・方向・シグナル」キーで同一通知を一度に限定するため、過去足を遡って通知しません。

## Discord / GitHub Actions

GitHub リポジトリの **Settings → Secrets and variables → Actions** に次を登録します。

* `DISCORD_WEBHOOK`（任意：未設定なら通知をスキップ）
* `EDINET_API_KEY`（EDINET APIからファンダメンタルを取得。値はログへ出力しません）

朝会はEDINETコードリストをキャッシュし、JPX公式の上場銘柄配布ファイルで証券コードを確認してから、
最新の有価証券報告書・半期報告書等のXBRLを取得します。明示された当期・前期だけから前年比を計算し、
候補CSVの現在値と明示されたEPS・BPS・実績配当を使ってPER・PBR・実績配当利回りを計算します。
取得元、時刻、書類ID、参照URL、失敗理由は `data/fundamentals_audit.csv` に保存し、取得失敗時も朝会を継続します。
EDINETだけでは会社予想・上方下方修正・重要適時開示が不足するため欠損のままとし、必須11項目は緩和しません。
非公式HTMLスクレイピング、推測・補完、J-Quants、TDnet自動取得はこの最小構成に含みません。

`.github/workflows/update_stocks.yml` は毎週日曜12:00 UTC（JST 21:00）に一覧を更新し、変更時だけcommit/pushします。`anti_daily_scan.yml` は平日09:00 UTC（18:00 JST、30分timeout）に backtest → scanner の順、`anti_intraday_alert.yml` は平日00:00～06:59 UTCに5分間隔で起動します。各ワークフローはGitHubの **Actions** タブで選択し **Run workflow** から手動実行できます。日足Discord通知はS/Aをスコア順に `scan.discord_max_alerts`（既定20）件まで送ります。全銘柄スキャンは通常数分～30分程度を想定しますが、無料APIの応答・レート制限に依存します。結果をcommitするため `contents: write` を使用し、ブランチ保護時はartifact等への変更が必要です。

`morning_investment_meeting.yml` は月～金06:30 JSTまでの完了余裕を確保するため05:45 JST（前日20:45 UTC）にスキャンを開始し、8:30 JST（前日23:30 UTC）再確認、15:30 JST（06:30 UTC）大引け後、金曜17:00 JST（08:00 UTC）週次会議を実行します。すべて `workflow_dispatch` で手動実行できます。Discord Secret未設定時は送信だけを安全にスキップします。GitHub Actionsの混雑や無料データAPI障害による06:30超過は保証できないため、Actionsの実行履歴とDiscord到着を人間が監視してください。

`provisional_meetings.yml` は朝会と分離し、月～金21:00 JST（12:00 UTC）に夜会、土曜06:00 JST（金曜21:00 UTC）に週末投資会議を実行します。日曜は実行しません。夜会・週末会議は候補と翌朝／月曜朝の再確認条件だけを保存する provisional な会議で、主力・小口・注文方式・株数・損切り・利確・RR・資金管理を確定または変更しません。最終判断は朝会で最新ニュース、日経先物、TOPIX、為替、米国市場、日本2年・10年・30年金利、10年-2年スプレッド、気配を再確認して行います。

### Googleスプレッドシートへの会議記録

朝会、夜会、週末会議で既に決定された候補と理由は、独立した `src.google_sheets` からスプレッドシートの
先頭シート「会議記録」へ追記されます。新しい売買判定は行わず、同じ「日付・会議種別・銘柄コード」は
再実行時にも重複登録しません。認証情報の未設定、認証エラー、API障害、書き込み失敗はいずれも警告だけを
表示し、会議処理とDiscord通知は継続します。

1. Google Cloudでプロジェクトを作成し、Google Sheets APIを有効化します。
2. サービスアカウントを作成してJSON鍵を発行します。
3. 対象スプレッドシートを作成し、先頭シートを「会議記録」と命名して、サービスアカウントのメールアドレスへ編集権限を共有します。
4. GitHubリポジトリの Actions secrets に `GOOGLE_SPREADSHEET_ID`（URL中の `/d/` と `/edit` の間のID）と
   `GOOGLE_SHEETS_CREDENTIALS_JSON`（JSON鍵の全文）を登録します。

疎通確認は Actions の手動実行、または同じ2環境変数を設定したうえで
`python -m src.investment_meeting --kind morning --no-notify` を実行します。未設定時のfail-open確認は、
両環境変数を外して同じコマンドを実行し、警告後も会議レポートが生成されることを確認してください。

## ファンダメンタル・ゲート

朝会は `data/fundamentals_input.csv` の正規化済み公式開示を候補へ結合し、売上高・営業利益・経常利益または純利益の前年比、EPS、PER、PBR、ROE、自己資本比率、配当利回り、会社予想、決算日、業績修正、重要適時開示を10点満点で評価します。EDINET書類に比率自体がない場合は、同じ公式XBRLの純利益・自己資本・総資産が揃ったときだけROEと自己資本比率を算出します。入力元は EDINET、TDnet、企業IR、J-Quants、JPX に限定し、参照URLまたは開示識別子が必須です。株探・みんかぶ等のHTMLスクレイピングは行いません。当期・前期の公式値が両方あり、連結/単体、実績/予想、年間/四半期が一致すると確認して `comparison_basis_verified`（配当性向は `payout_basis_verified`、配当比較は `dividend_comparison_verified`）を明示した場合だけ、利益の黒字/赤字推移、売上高と営業利益の4象限、配当性向、増配・維持・減配・無配転落を算出します。片方でも欠けるか比較条件を確認できなければ「評価不能」または欠損とし、前期利益が負数なら通常の前年比率ではなく黒字転換・赤字転落等の分類を優先します。EDINET XBRLは連結コンテキストかつ同じ期間種別の当期・前期を機械的に確認します。候補CSVにはファンダメンタルスコアの全加点・減点理由も保存し、Discordには要約を表示します。

値は公式開示や契約済みサービスから確認した値をCSVへ投入してください。取得できない値は推測・前回値補完せず、会議成果物では項目ごとに「データなし」と記録します。必須11項目を満たさない、公式取得元でない、または参照先がない銘柄は「データ不足」となり、テクニカルが良くても主力になりません。公式データが一部だけ取得できた場合も取得済み項目から参考スコアと理由を保存しますが、データ充足ゲートは緩和しません。4点以下、下方修正、赤字転落、重大な悪材料も主力から降格します。各候補の取得元・取得日時・成功/失敗理由は `data/fundamentals_audit.csv` に追記されます。会議Markdownの監査表に加え、同名のCSVとJSONにも取得値・スコア・総合判定・判定理由を保存し、Streamlitは保存済み会議記録を表示します。
